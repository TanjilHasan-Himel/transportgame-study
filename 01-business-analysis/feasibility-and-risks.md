# Feasibility assessment and risk register

This is a bounded prototype assessment, not investment, legal or commercial feasibility certification. Evidence classifications follow [Context](problem-and-context.md).

| Dimension | Defensible conclusion | Missing evidence |
| --- | --- | --- |
| Technical | VERIFIED: implemented browser prototype, selected automated assertions and recorded local build/capture results, E03–E12 | Full journey, deployed behavior, production security and representative-device performance |
| Operational | DOCUMENTED: owner identifies usability/refresh problems, E01; PROPOSED corrective journey | Operator interviews, staffing/process validation, support and maintenance experience |
| Financial | VERIFIED: scenario/calculation helpers exist and have selected tests, E07/E08 | Current quotations, validated demand, complete tax/debt cash flow, acquisition/retention economics and field reconciliation |
| Commercial | UNKNOWN: no established traction or measured outcomes in the evidence | Paying customers, addressable-market research, willingness to pay or sustainable operating model |

## Risk register

Severity is qualitative analyst judgement (INFERRED), not a measured probability.

| ID | Risk / severity | Evidence status | Proposed response / responsibility |
| --- | --- | --- | --- |
| R1 | Credential, private evidence or personal-data disclosure / critical | Bounded scans only; comprehensive security UNKNOWN | Owner/reviewer approves exact public tree; never mirror source/history |
| R2 | Different trip paths produce inconsistent money/time / high | Helper assertions exist; whole-path parity UNVERIFIED | Development: equal-input integration, repeat completion and reload tests |
| R3 | Refresh/slot/offline behavior blocks or alters play / high | Owner report DOCUMENTED; supported save units VERIFIED | Development: reproduce with preserved sample saves; no storage-reset shortcut |
| R4 | Map precision or UI wording misleads users / high | Heuristic custom corridors and simulated position VERIFIED, E09 | Product: label approximation; validate routing separately from permits |
| R5 | Cloud ownership/device conflicts / high | Live isolation UNKNOWN; inspected contract disagreement, E13 | Owner/security reviewer: agreed contract and two-user permission tests before support claims |
| R6 | Dependency issues or resource-dependent verification / high | Recorded audit and latest local QA in testing report | Development: isolated dependency triage and reproducible resource-aware checks, no forced upgrades here |
| R7 | Unsupported market/ROI claims / high | Real demand, prices and outcomes UNKNOWN | BA/owner: independently validate inputs and document uncertainty |
| R8 | Asset redistribution/licensing / medium | Attribution retained; independent permission audit UNKNOWN | Owner: review third-party terms before wider reuse; do not infer rights from a URL |
| R9 | UI/a11y/performance gaps / medium | Desktop smoke only; broader certification UNKNOWN | Product/QA: representative users, keyboard/mobile checks and measured budgets |

No monetary loss estimate, benefit percentage or verified risk reduction is invented. Publishing a truthful limitation is not remediation of the underlying risk.
